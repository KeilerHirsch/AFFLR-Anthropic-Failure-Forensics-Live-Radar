# Security and Responsible Disclosure

This repository documents failures and public upstream reports. It is **not** a drop box for secrets, credentials, private support transcripts, personal data, or embargoed vulnerability details.

## Do not publish here

- API keys, tokens, passwords, cookies, or session identifiers;
- private HackerOne report contents that are not already public;
- personal or medical data;
- unreleased exploit details that could create avoidable risk;
- evidence whose publication would violate an active disclosure agreement.

## How historical disclosures are referenced

Private disclosure systems may be mentioned only by minimal metadata needed to connect a timeline, such as a report identifier and disposition. Public technical claims should rely on public issues, public artifacts, reproducible tests, or redacted evidence.

## Reporting a new security issue

Report security issues to the affected vendor through its current official disclosure channel first. Add a public case here only when publication is appropriate and the evidence can be presented safely.

This repository distinguishes **security impact**, **technical failure**, and **attribution confidence**. They are not interchangeable.
